工作口语课 · S001

三分钟讲清我做的一个功能

Demo Your Feature in Three Minutes

  • 8 句脚本
  • 只用 Lesson 1–2 的骨架
  • 建议用豆包语音练

这一课的唯一收获：轮到你演示时，能顺着「这是什么 → 以前多糟 → 我们改了什么 → 现在什么样 → 还没做完的 → 有问题吗」六步说满三分钟， 中间不用停下来找词。

下面八句全部只用已经学过的句子骨架，一条新的都没有。 骨架表在已学骨架总表—— 先能盖住英文说出中文对应的骨架，再来练这一课。

01什么时候用

三种场合，说的是同一套话：

  • 评审会上轮到你：屏幕上放着你的改动，五六个人等你开口，你有三分钟。
  • 站会上被问「你昨天那个东西怎么样了」：只有三十秒，说前三句就够。
  • 外国同事在群里 @ 你，让你讲讲这个功能怎么用：这时候是打字， 但句子结构和口语完全一样，先把口语练顺，写的时候就不会中式。

中文汇报的习惯是「先说背景，再说过程，最后说结果」， 英文演示反过来——第一句就要让人知道这东西是干什么的。 下面八句的顺序就是按这个来的，别自己调。

02八句脚本

练法：盖住下面的英文，只看中文意图，每句出声说三遍。 说的时候把 [ ] 里的内容换成你自己那个功能。八句都能顺出来，三分钟就填满了。

  1. 第 1 步 · 这是什么 这个任务负责导出月度报告，并把它写到共享盘。

    This job exports the monthly report and writes it to the shared drive.

    用「一般现在时（习惯）」——说一个功能常态是干什么的，就用现在时。 主语是三单，两个动词都要加 -s。开口第一句不要说背景，直接说它是干什么的。

  2. 第 2 步 · 以前多糟 上个月队列变得很长，导出要跑四十分钟。

    Last month the queue got very long, and the export took forty minutes.

    用「get + 形容词」说变化（变得很长），用「过去时肯定」说已经发生的事。 last month 前面不加 in。这一步别省—— 不说以前多糟，别人不知道你的改动值多少。

  3. 第 2 步 · 以前多糟 大文件的请求会失败，而且我们拿不到任何日志。

    The request failed on large files, and we did not get any logs.

    用「过去时否定」：did not 后面必须是原形 get，不是 got。 这是中国开发最常犯的一处，说之前先在心里过一遍。

  4. 第 2 步 · 以前多糟 用户关掉页面时，任务还在跑。

    The task was still running when the user closed the page.

    用「过去进行时」说当时正在发生的事，和 when 后面的一般过去时错开。 一句里两个时态并存，这正是英文讲事故最自然的说法。

  5. 第 3 步 · 我们改了什么 所以我们改了导出链路，上周上线了。

    So we changed the export path. We shipped it last week.

    两句都是「过去时肯定」，拆开说比挤成一句好懂。 ship 是工程口语里的默认动词，比 release 更像人话； last week 前面同样不加介词。

  6. 第 4 步 · 现在什么样 现在报告三分钟就生成好了，而且总是落在同一个目录。

    Now the report is generated in three minutes, and it always lands in the same folder.

    前半句用「一般现在时被动」（is + 过去分词）—— 说系统行为时，被动比「我们生成了报告」自然得多。 后半句用「频率副词位置」：always 放在实义动词 lands 前面。 给数字，四十分钟变三分钟，比「快了很多」有说服力。

  7. 第 5 步 · 还没做完的 大文件那条路我们还在测，旧接口我们计划下周下掉。

    We are still testing the large-file path, and we plan to remove the old endpoint next week.

    前半句用「现在进行时 + still」（be + still + 动词 ing）； 后半句用一般现在时 plan（主语 we 接原形）说当前的计划，to 后面跟 remove 原形。 主动说未完成的部分，比被人追问出来强。

  8. 第 6 步 · 有问题吗 我这边讲完了。关于灰度发布，大家有什么问题吗？

    That is all from me. Do you have any questions about the rollout?

    用「一般现在时疑问（do）」：Do + 主语 + 动词原形。 That is all from me 是标准的收尾，比 I finish 或 That's all 更完整， 也明确把话头交回去了。

这八句是我们自己写的练习句，不是文档原文。它们只用 已学骨架总表里 Lesson 1–2 那 16 条骨架， 每句下面的说明都写了它用的是哪一条。

03别这么说

这三句是中文直译过去最容易脱口而出的，都在演示场合出现过。上面是该说的，最下面那条是别人听到的。

说效果夸自己的改动

The export is much faster now. It takes three minutes.

导出现在快多了，三分钟就跑完。

perfect 本身已经是顶格，不能加 very； 而且 function 在英文里指数学函数或代码里的函数，产品上的「功能」要说 feature。 更根本的问题是：英文讲改进靠具体结果，不靠程度副词。给数字，别给形容词。

别这么说：「This function is very perfect now.」

说进度回答「做完了吗」

We shipped this yesterday.

这个我们昨天上线了。

yesterday 已经把时间锁死了，再加 already 是中文「已经」的直译， 英文里显得多余。finish 说的是「做完了」，ship 说的是「上线了」—— 演示场合你要传达的永远是后者。

别这么说：「We already finished this function yesterday.」

收尾提问讲完之后

Does that make sense? / Did I get that right?

我这样讲清楚了吗？／我理解得对吗？

Do you understand 在会议上听起来像在质疑对方的理解力， 而且 what I say 的时态也不对（刚讲完的事该用 said）。 换成 Does that make sense，责任落在「我有没有说清楚」上， 对方才敢真的提问。两句都用已经学过的骨架： Does + 主语 + 原形，Did + 主语 + 原形。

别这么说：「Do you understand what I say?」

04拿去和 AI 练

这一课必须开口，看文字不算练。推荐用豆包的语音通话： 把下面的提示词粘进去建一个智能体，然后直接跟它说话。 它扮演评审会上的外国同事，会打断你、会追问，就像真的一样。

陪练 · 演示彩排。建议用豆包语音通话；没有语音时，用 Trae / codex 打字也能练结构。

练完一次不够。同一个提示词，把功能换成你手上另一个改动再练一遍—— 第二遍你会发现卡壳的地方变了，那就是真的进步了。 想让它按书面标准批你写的稿子，用AI 提示词库里的「批改」。
