# 教学笔记

## 学习者画像

- 起点：初中基础，偏薄。词性、句子成分需要从头讲。
- 终点：读懂英文技术资料（文档、报错、issue、论文）。
- 节奏：每天一课。**不卡时长**，以「走完四步闭环」为完成标准（见下）。
- 技术栈假设：Java / JVM 生态（Gradle、Spring、Maven、报错栈）。
  这是**可修订假设**，依据仅为仓库根 `AGENTS.md` 举例时提到 `java-gradle`，学习者未明确确认。
  一旦发现真实主力栈不同，立刻改这一条，并回头替换已产出课程第 07 节的桥接句。

## 课程结构：固定的九个环节

每课都走同一套结构。这是 2026-10-20 三轮 grilling 后定稿的，**不要随课程变动**。
样板见 [lessons/0001-a-private-conversation.html](lessons/0001-a-private-conversation.html)。

| # | 环节 | 做什么 | 用哪个组件 |
| --- | --- | --- | --- |
| 00 | 热身检索 | 三题摸底/复现上一课的骨架，明确标注「不是考本课」 | `quiz.js` |
| 01 | 今天的技能 | 一句话给出技能名 + 为什么读技术资料需要它 + 一句真实技术句作 hook | `.skill` / `.bridge` |
| 02 | 最小装备 | 8 个左右核心词卡 + 最多两张对照表，明确写「不要背」 | `.words` / `table` |
| 03 | 拆解示范 | 3 句，每句走同样的三步，逐步演示「我是怎么想的」 | `sentence.js` demo 模式 |
| 04 | 你来拆 | 8 句左右，点词找成分，点错标红并告知它其实是什么 | `sentence.js` find 模式 |
| 05 | 中译英回译 | 4 句，先写完再展开对照，草稿自动存本地 | `translate.js` |
| 06 | 混合检索 | 6 题，类型故意打乱（找错/词义/句型/理解/词性/搭配交错） | `quiz.js` |
| 07 | 桥接 | 4 句真实技术原文，逐字摘录，显式映射「骨架 = 第 03 节第 N 句」 | `.bridge` |
| 08 | 产出与收口 | 仿写三句 + 自检清单 + 60 秒默写 | `.task` / `.checklist` / `.recall` |

## 四步闭环：唯一的质量锚点

时长约束已取消，改用四步闭环防膨胀、防注水。**走完就结束**，不凑时长，也不砍环节。

1. **示范**（03）——我做给你看，重点是思考顺序而非答案。
2. **你练**（04 + 05）——点词拆解 + 回译重建。回译比选择题难，也比选择题有用。
3. **检索**（00 + 06）——摸底是间隔检索，混合是交错检索。都要求「不要往回翻，凭记忆答」。
4. **产出**（08）——写出来。这是把知识变成能力的唯一环节。

判断一课是否合格：四步各占到了吗？第 04、05、06 节能不能不回看第 02、03 节就完成？
若某一步只能靠翻上面才做得了，那是 fluency 错觉，不是掌握。

## 教学偏好与约定

- 中文讲解为主，英文术语首次出现时给中文对照。
- 每课只给一个明确收获，宁浅勿深。
- **课文原文必须核对可信来源，不凭记忆书写**；每课页脚标注全部来源。
- **桥接句同样必须核对官方来源**，优先一手文档（release notes、user guide、changelog），
  不用二手博客；逐字摘录，不改写，并附来源链接与所在小节名。
- 测验即时反馈，选项严格等长（中文选项对齐字数），正确答案位置分散，避免连续同位。
- 中英混排时，中文与英文/数字之间加一个半角空格。
- 每课必须能独立打开：纯静态、无构建、无外部依赖，`file://` 直接双击可用。

## lesson 与 reference 的分工

两者不重复。课程里的课文是**练场**，reference 里的是**手册**。

- `lessons/`：交互式，课文句子作为拆解练习的语料，批注只讲与本课技能相关的点。
- `reference/lesson-0N-text.html`：完整批注版，含全部生词、搭配、文化注释，可打印，供课后查阅。
- `reference/*.html`（语法速查）：只讲语法规律，不绑具体课文。
- `reference/review.html`：**唯一需要反复回来的文档**。每完成一课在第 01、03、04 节追加行，
  并在第 06 节记一行更新记录。不重写已有内容——这张表的价值在于越来越长。

## 文件与命名约定

- 课程：`lessons/000N-<dash-case>.html`，编号递增，不复用。
- 课文批注：`reference/lesson-0N-text.html`。
- 共享样式：`assets/course.css`——所有页面统一引用，保证整套课看起来是一门课。
- 组件：`assets/quiz.js`（选择题）、`assets/sentence.js`（句子拆解）、`assets/translate.js`（回译）。
  三个都是 IIFE + `"use strict"` 原生 JS，通过 `data-*` 属性声明式绑定，不含任何课程数据。
- 学习记录：`learning-records/000N-<dash-case>.md`。
  **按缺口记，不全对就不建**——全对的课不留档；只有在连续两次错同一个骨架、
  或到达第 8 / 16 天复习节点仍没过关时，才建一份缺口记录。
  文件名用缺口本身命名（例：`0002-plural-subject-failed.md`），不用课号命名课。
  一份记录写清：缺口是什么、怎么发现的、已用什么补丁、什么条件下回看。
  这样 96 课下来只会有十几份文件，但每份都是真问题，agent 读它算最近发展区（ZPD）时不需要过滤噪音。
- 词汇表：`reference/glossary.html`——待学习者能正确使用某个术语后再收录，不做成词典。
  **第 1 课不触发，尚未创建。**

## 组件接口约定（写课程时必须遵守）

`data-translate` 的值会拼进 localStorage 键（前缀 `nce-english:translate:`），
**必须全工作区唯一**，建议 `l<N>-tr-<M>`。

`data-quiz` 同理，前缀 `nce-english:quiz:`，建议 `l<N>-<节号>`（例 `l1-00`、`l1-06`）。
加了 `data-quiz` 的测验才会出现记录条（上次记录 · 复制为 Markdown · 清空）；
不写这个属性则组件完全无状态，行为与加之前一致。
记录条复制出来的是「1 起算的选项序号 + 对错 + 用时」，可直接粘进 learning-records。
**用时是粗测**：从上一题作答或页面载入算起，含读题时间，不要当精确指标用。
`sentence.js` 的讲解文字必须写在 `.sent-fb` 的 `data-text` 属性里，不能写在元素内容中
（JS 会用 `textContent` 覆盖它）。

`data-step` 从 1 开始，累积点亮（点过的不熄灭），符合「拆解逐层搭建」的认知顺序。
