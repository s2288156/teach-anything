# 教学笔记

结构性决策见 [docs/adr/](docs/adr/)，本文件不复述。

## 学习者画像

- 起点：初中基础，偏薄。词性、句子成分需要从头讲。
- 终点有两条，同等重要：
  1. 读懂英文技术资料（文档、报错、issue、论文），不必每句都先翻译；
  2. 用英文把工作说清楚——公司内部的英文演示（把自己开发的功能讲成课程），
     以及跨国会议里的技术讨论（即兴问答、澄清、委婉不同意）。
- **定位：纸质教材与视频课程的配套导学手册，页面纯阅读。** 边界与分工见 [MISSION.md](MISSION.md)。
- 技术栈与语料范围见 [MISSION.md](MISSION.md) 的 Constraints；Lesson 1 第 05 节的
  Gradle 句子属于该栈，保留不改。

## 课程结构：固定的七个环节

每课都走同一套七环节结构，**不要随课程变动**。
样板见 [lessons/0001-a-private-conversation.html](lessons/0001-a-private-conversation.html)。

| # | 环节 | 做什么 | 用什么样式 |
| --- | --- | --- | --- |
| 01 | 这一课学什么 | 一句话给出本课句型 + 为什么读技术资料需要它 + 一句真实技术句作引子 | `.topic` / `.docs` |
| 02 | 生词和搭配 | 4 个搭配块，每块含中文意图与一个典型误用，明确写「不要背单词表」 | `.words` / `table` |
| 03 | 一句一句拆开看 | 课文核心 3–4 句，每句书面走同样三步（找动词 → 定时间 → 切主干），读者跟着看「我是怎么想的」 | `.sentences` |
| 04 | 平时聊天怎么说 | 3 个现实场景，每个 2–3 句，各配一条「别这么说」对照；场景在同事闲聊 / 电话或约人 / 日常安排之间轮换 | `.chat` |
| 05 | 技术文档里怎么写 | 一段连续的真实文档原文（同一页同一小节连续 3 句），逐字摘录，逐句标出对应第 03 节哪句的句型 | `.docs` |
| 06 | 开会和演示怎么说 | 6 行：3 句演示用（介绍功能 / 解释改动 / 回答提问）+ 3 句会议应对（请对方重说 / 复述确认 / 委婉不同意）。每行「中文意图 → 英文句 → 标注用了第 03 节第 N 句的句型」，节末一句「盖住英文，看中文说三遍」 | `.speaking` |
| 07 | 拿去和 AI 练 | 三个 AI 角色（陪练 / 批改 / 出题）的复制提示词，各标注建议工具 + 一句话复习提醒 | `.prompt` / `prompt.js` |

第 06 节只准用**已学过**的句子骨架（本课的 + `reference/review.html` 里的），不引入新语法。

练习不由本目录承担；想练时两个出口——纸质教材本身有习题，第 07 节的「出题」角色能出回译与仿写题。

## 教学偏好与约定

- 中文讲解为主，英文术语首次出现时给中文对照。
- **写中文用日常说法，不生造压缩术语**（「装备」「桥接」这类词已废弃，见
  [ADR 0005](docs/adr/0005-plain-chinese-section-names.md)）；必要时直接用英文。
- 每课只给一个明确收获，宁浅勿深。
- **课文原文必须核对可信来源，不凭记忆书写**；每课页脚标注全部来源。
- **第 05 节的技术文档原文同样必须核对官方来源**，优先一手文档（release notes、user guide、changelog），
  不用二手博客；**整段逐字摘录，不改写、不跨页拼接**，并附来源链接与所在小节名。
  允许我们自己写的句子只出现在第 06 节（口语脚本本来就是造的，页面上标明是练习句）。
- **每课必须讲清「现实中怎么用」**：第 04 节取自上班族的真实对话，第 06 节取自学习者自己的
  工作会议与演示；两节都要求至少有一句是第二天就可能说出口的。
- 25 课起技能阶梯转向技术英语的真实难点：名词化短语、长介词链、被动语态密集、插入语。
  句子骨架的定义随之扩为「主干 + 时态 + 修饰块」，01 节的技能名从时态名改为结构名
  （例：从「现在完成时」改成「一串名词修饰里先找中心词」）。1–24 课不动。
- 中英混排时，中文与英文/数字之间加一个半角空格。
- 每课必须能独立打开：纯静态、无构建、无外部依赖，`file://` 直接双击可用。

## AI 交互：只做提示词，不调接口

课程不调用任何 AI API。交互方式是「复制提示词 → 粘到任意 AI 对话」，
组件见 `assets/prompt.js`，提示词库见 [reference/ai-prompts.html](reference/ai-prompts.html)。
三个角色的按钮统一嵌在第 07 节，一节收口。

三个 AI 角色固定：

| 角色 | 做什么 | 建议工具 |
| --- | --- | --- |
| 陪练 | 扮演同事，用英文一问一答，把本课句型用进真实对话；也带练第 06 节的脚本句 | 豆包（语音通话） |
| 批改 | 收学习者写的句子（教材习题、自发消息），按准确 / 时态 / 地道三条标准批改 | Trae / codex |
| 出题 | 出三句中文让学习者回译，答完公布参考答案并打分；替代纸质默写 | Trae / codex |

提示词本身用中文下指令，角色扮演部分要求 AI 说英文。
输出契约统一：**先总评、只改一处、再给升级版**——一次只改一个毛病，
避免 AI 一次列出十几条错误把学习者淹掉。

提示词库另备两份不绑具体课文的模板：

- **AI 项目系统指令**：句子骨架库占位 + 输出契约 + 三个角色，一次贴进 AI 项目
  （豆包智能体 / Trae 项目 / codex）即可长期复用。课程页不收集学习结果，
  个性化记忆全靠这一份在 AI 侧累积。
- **每周合成复习材料**：让 AI 用本周已学句型写一段 150 词的仿真 issue 或功能介绍。
  这类材料只存在于 AI 对话里，不落成本目录的文档，避免 `review.html` 膨胀。

学习结果不回流到课程生成：下一课只依据教材进度与本页结构生成，不做学情反馈。

## lesson 与 reference 的分工

两者不重复。课程页是**导学**，reference 里的是**手册**。

- `lessons/`：七环节课程页，批注只讲与本课句型相关的点。
- `speaking/`：工作口语课，4 节，只用已学句型。
- `reference/lesson-0N-text.html`：全文批注版，含全部生词、搭配、文化注释，可打印，供课后查阅。
- `reference/*.html`（语法速查）：只讲语法规律，不绑具体课文。
- [reference/ai-prompts.html](reference/ai-prompts.html)：提示词库，三个角色各一份通用模板、
  两份跨课模板（系统指令、每周复习），每课再各写一份。
- [reference/review.html](reference/review.html)：**唯一需要反复回来的文档**。每完成一课在
  第 01、02、04、05 节追加行（第 02 节现在同时收聊天句与工作句，来源标 `L<N>·聊天` /
  `L<N>·演示` / `L<N>·会议`），并在第 07 节记一行更新记录。不重写已有内容——
  这张表的价值在于越来越长。学习者只来回看，不在这里登记学习结果。

## 组件接口约定（写课程时必须遵守）

`prompt.js` 用 `data-copy-prompt="<template-id>"` 绑定按钮，从对应 `<template>` 读取提示词：
`<template>` 内用多个 `<p>` 分段，JS 按空行拼接；`<br>` 会转成换行。
按钮点击后短暂显示「已复制」；`file://` 下 Clipboard API 不可用时自动退回 `execCommand`；
两者都失败时把提示词展开成可选中的文本块并自动全选。

除此之外页面不放任何 JS 行为：不生成测验、不记录作答、不读写 localStorage、不嵌音频。
